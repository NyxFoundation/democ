## 外部データ

### リスクの順位

[OWASP Top 10:2025 A01 Broken Access Control](https://owasp.org/Top10/2025/A01_2025-Broken_Access_Control/)

第1位はアプリケーションのセキュリティリスクの順位で、単一CWEの年間件数順位ではない。
動画では「脆弱性リスク」と表現する。OWASPのリストは認可の欠落以外のアクセス制御問題も含む。

### 年間120件の定義

集計日：2026-11-07。
NVD CVE API 2.0で、公開日が2025-01-01〜2025-12-31に入り、CWE-862
(Missing Authorization) またはCWE-863 (Incorrect Authorization) に分類されている
CVE IDを取得。Rejectedを除き、CVE IDで重複を除外すると120件。

- CWE-862の四半期別件数：36 / 18 / 7 / 13（計74）
- CWE-863の四半期別件数：18 / 5 / 9 / 14（計46）
- 重複を除いた合計：120
- APIの各クエリURL、件数、全120 IDは data/annual-cves-2025.json
- 再取得コマンド：
  uv run python3 tools/count_cves.py --year 2025 --out out/nyxis/data/annual-cves-2025.json

[NVD API仕様](https://nvd.nist.gov/developers/vulnerabilities) /
[クエリ例：2025年1〜3月、CWE-862](https://services.nvd.nist.gov/rest/json/cves/2.0?cweId=CWE-862&pubStartDate=2025-01-01T00%3A00%3A00.000&pubEndDate=2025-03-31T23%3A59%3A59.999&resultsPerPage=2000)

これは「世界で発生した攻撃・被害の件数」でも「OWASP A01全体の件数」でもない。
未報告・未分類の脆弱性は含まれず、分類更新で値は変わる。
画面には年とCVE報告件数であることを本文で示す。CWEや取得日などの詳細はこの制作ノートにのみ記載する。
以前の19,013件はOWASP Top 10:2021の集計値であり、年間値としては使わない。

## 正しさとビルド結果

[Nyxis README](https://github.com/NyxFoundation/nyxis) /
[保証の前提](https://github.com/NyxFoundation/nyxis/blob/main/ASSUMPTIONS.md) /
[実際の拒否検査](https://github.com/NyxFoundation/nyxis/blob/main/scripts/check-schema-rejection.sh)

Nyxisが示すのは「承認したポリシーが許す範囲を超える操作を発行しない」こと。
ポリシー自体が業務要件どおりであることまで、ビルドは判定しない。
意図に反して広いポリシーを書いても、そのポリシーを守る証明は成立しうる。
したがって「ビルド失敗＝安全でないことが証明された」とは表現しない。
失敗は「保証を確認できなかった」であり、スキーマ不整合はその具体例。

場面5のエラーはNyxisの検査スクリプトが扱う実例：
update Post(title, bodyy) のbodyyがスキーマのPostに存在せず、ビルドが失敗する。
画面は挙動を再現するデモであり、このリポジトリでNyxis本体をビルドした記録ではない。
表示のビルドログは実ログの行列を忠実に再現するものではなく、処理の要約。
最小ポリシーは「作者のみreadPostを許可」。公開済み投稿、管理者などを含む完全なサンプルは省略。

## Leanと立体表現

[Lean公式：Elaboration and Compilation](https://lean-lang.org/doc/reference/latest/Elaboration-and-Compilation/)

「証明したい命題Pを型とする証明項tを、エラボレータが構築する。
カーネルが、その項が主張された型を持つことを検査する」が説明の軸。
カーネルが証明探索を行って依存ツリーを生成するとは説明しない。

定理名 Nyxis.Runtime.authorization_safety は実物。
日本語の命題はその性質を短く述べたもの。
枝の形、節の数、依存関係の配置、葉から走るチェックの順序は説明用の概形で、
実際の証明依存グラフの抽出結果やカーネルの実行トレースではない。
「t : P」は型と証明の対応を表す記法。

3Dはこの場面だけ。球状の依存グラフ、カメラの周回、項の出現、型検査の波をBlenderで生成する。
字幕と一時表示するノード内容はHTMLから透過PNGとして切り出す。
文字はレンズ効果の後に合成し、球体・ハイライトの輪・接続線は立体空間に置く。
Blender 5.0 / EEVEE、1600×1000、25fps、450フレーム（18秒）。
生成された kernel.mp4 があれば、HTMLプレビューでもその動画を再生する。
生成前はHTMLの概形アニメーションで全体の流れを確認できる。

## 表示方針

場面番号付きの英語小見出しと、小さな出典・保証範囲・概念図の注釈は表示しない。
出典と保証範囲はこのノートに残す。補助的な英語の説明や枝に常駐する小さな補題名も省く。
注目したノードだけ、読み取れる大きさで約2秒の内容表示を行う。GitHub URLは締めの本文に大きく表示する。

## 場面転換

全7か所を0.4秒のクロスフェードでつなぐ。場面の末尾を先に消す処理と、
次の場面までの0.42秒の待ちをなくし、途中で背景だけになる瞬間を避ける。
ブラウザでは前の画面を固定してから次を準備し、Blender動画の最終フレームも保持する。
MP4は各素材の末尾・先頭を10フレーム重ねる。edit/dissolve.pyが境目の映像を生成し、
MLT / Kdenliveの双方に同じ素材を並べる。3D自体を再描画する必要はない。
録画は自動再生を止めた状態から指定した場面だけを開始する。

## 依存ツリーのモーション改訂

参考として確認した作例：
- One Road, Luminous Trails – Procedural Geometry Animation:
  https://oneroad.co.uk/es/?dt_portfolio=luminous-trails-procedural-geometry-animation
  公開された作例画像と制作解説を確認。曲線の流れ、発光の強弱、密度と読みやすさ、
  奥行きの分離を参考にした。Vimeo埋め込み映像はこの環境から再生できなかった。
- Territory Studio, Cascade – Immersive Data Experience:
  https://territorystudio.com/project/cascade-immersive-data-experience/
  公開の作例画像と解説を確認。個々の粒子を大きな流れとして見せる考え方を参考にした。
- Vasco Asturiano, 3D Force Graph / Camera Auto Orbit:
  https://vasturiano.github.io/3d-force-graph/example/camera-auto-orbit/
  動くデモをブラウザで表示し、6秒間隔の画と公開コードを確認。
  ノードの位置関係がカメラの回り込みで理解できる視差の使い方を参考にした。

映像素材は流用せず、Blenderで新たに構成した。

18秒の内部構成：
- 導入：中心の主定理から、球の全方向へ依存グラフが広がる。
- 展開：空間的にまとまった依存関係を、曲線で順に伸ばす。
- 周回：球全体が画面内に収まる距離を保ち、カメラが回り込む。補題と構造体の内容を一時表示する。
- 検査：末端の項から、明るい光点と短い軌跡が親へ流れる。
  親のチェックは、子からの到着後に開始する。
- 確定：金色の光が球の外側から中心へ集まり、t : Pを短く表示する。

旧版の床グリッドは外し、背景を暗い空間と控えめな粒子にした。
物理的な焦点移動、短いモーションブラー、控えめなグローを使う。
見出しと字幕はレンズ効果・グローの後に合成し、読める状態を保つ。
小さなラベルや脚注は追加しない。依存関係・チェックの動きは引き続き説明のための比喩である。

## 球体ノードと内容表示の改訂

- すべての定理・項を48分割×24リングのUV球とスムーズシェーディングで描く。
  主定理の板、筐体、定理専用の物理パネルを廃止した。
- 枝は13点の折れ線から、正確な3次ベジェ曲線へ変更。
  各ノードの入射・出射ハンドルを揃え、分岐で接線が急に変わらないようにする。
  光点も折れ線の位置キーからFollow Pathへ変更し、枝の曲線に沿って連続移動する。
- 未検査は暗めの青、検査済みは明るい金色。白に近い光点、枝の輝度差、球体の脈動を併用し、
  青と緑の色相差だけで状態を見分ける必要をなくした。
- 約2秒ずつ、注目球体の輪と接続線に連動して文字を表示し、その後は消す。
  主定理→trace_authorized→Runのフィールド→証明成立の順。背景は角のない光量の落ち方で抑える。

表示内容はローカルのNyxisソースを確認した。
参照リビジョン: 30bf2d1c96bd0f7b7a23db5aa222da62cb3adc71（banri-nyxis）。
Nyxis/Runtime.lean の authorization_safety は trace_authorized を直接使用する。
Run は runHandler / handleRequest の戻り値を表す構造体で、4フィールドをそのまま表示する。
trace_authorizedの表示は結論のAuthorized部分の抜粋で、完全な定理の型ではない。
主定理の日本語表示も保証の一部を説明した短縮表現である。
グラフ全体の枝数・配置・チェック順は説明用の構成で、抽出済みの完全なLean依存グラフではない。

変更前の3D、Blenderファイル、完成動画、スクリプトは
build/previous/before-spherical-nodes/ に保存した。


## 球状の依存グラフと添削の反映

「球体」は個々のノードを大きな球として強調する意図ではなく、依存ノードの集合が
球体状に連なるという意図。旧版の一方向に広がる樹形を、中心から全立体角へ広がる構成に変更した。

- 外周216ノードをフィボナッチ球面に配置し、すべて中心から同じ半径14.2に置く。
- 四面体方向の4群を起点に、球面上の近い依存先を再帰的にまとめる。
  半径3.4 / 6.1 / 9.1 / 11.7 / 14.2の層に4 / 12 / 36 / 108 / 216ノードを配置する。
- ノードは小さな光点。主定理も中心の光点とし、主定理だけを大きな球として押し出さない。
- 曲線の接線は各ノードの半径方向に揃える。チェックの光は外周から中心へ戻る。
- カメラは球全体が見える距離で連続周回し、手前と奥の枝の発光強度にも差を付ける。
- 18秒・450フレームと短いクロスフェードは維持する。

文言はexamples/nyxis/nyxis.yamlへのユーザーの添削を反映した。
ただしCVEは被害の発生件数を表さないため、「年間被害件数」は
「年間の脆弱性報告件数（2025年CVE）」に補正した。
「正しい認可を、簡単に実装する。」は意味の区切りで2行に配置する。
2行の事故例見出しは左右ペインを50px短くして字幕の領域を確保した。
3D字幕は添削後の4パートに対応し、削除された5番目の字幕は書き出さない。

変更前の映像・Blender・台本と、反映前の添削原本は
build/previous/before-globe-layout/ に保存した。
